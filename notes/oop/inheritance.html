Inheritance

Inheritance lets a derived class reuse a base class. It models an is-a relationship, keeps shared state in one place, and reaches base members through public, protected, and private inheritance.

Unit prose and C++ examples are written from the syllabus and standard C++.

Recall cues

  1. What do public, protected, and private inheritance change?
  2. How do single, multiple, hierarchical, multilevel, and hybrid inheritance differ?
  3. How do derived constructor and destructor chains run?
  4. How does aggregation differ from inheritance, and when is a virtual base class needed?
  5. What causes ambiguity in multiple and multipath inheritance, and how is it resolved?

Part 1 · Base and Derived Classes ★★★

Unit 5.1 of the syllabus.

1. Inheritance: base and derived classes with access specifiers ★★ EXAM 10

A base class holds state and behaviour; a derived class inherits it. The inheritance list names the base class and uses public, protected, or private to set member access in the derived class.

Part 2 · Inheritance Forms ★★★

Unit 5.2 of the syllabus.

2. Inheritance forms: single, multiple, hierarchical, multilevel, and hybrid ★★ EXAM 10

Single inheritance takes one base. Multiple inheritance takes several bases. Hierarchical links one base to many derived. Multilevel chains a derived from a derived. Hybrid combines two or more inheritance forms.

Part 3 · Constructor and Destructor Order ★★

Unit 5.3 of the syllabus.

3. Constructor and destructor order in derived classes ★★ EXAM 10

Base constructors run before derived constructors, and destructors run in reverse order. A virtual destructor lets a base destructor clean up through a derived pointer.

Part 4 · Aggregation, Ambiguity, and Virtual Base Class ★

Unit 5.4 of the syllabus.

4. Aggregation vs inheritance, Ambiguity, and Virtual Base Class

Aggregation is a has-a composition without an is-a relationship, so inheritance is not implied. Ambiguity arises when two bases define the same name. A virtual base class resolves the diamond problem by sharing one base.

#include <iostream> // Multilevel inheritance: constructor order runs Base, Level1, Level2. class Base { public: Base() { std::cout << "Base ctor" << std::endl; } virtual ~Base() { std::cout << "Base dtor" << std::endl; } }; class Level1 : public Base { public: Level1() { std::cout << "Level1 ctor" << std::endl; } }; class Level2 : public Level1 { public: Level2() { std::cout << "Level2 ctor" << std::endl; } }; // Virtual base class: shared Base2 is constructed once despite two paths. class Base2 { public: Base2() { std::cout << "Base2 ctor" << std::endl; } }; class SideA : virtual public Base2 { public: SideA() { std::cout << "SideA ctor" << std::endl; } }; class SideB : virtual public Base2 { public: SideB() { std::cout << "SideB ctor" << std::endl; } }; class Level3 : public Level2, public SideA, public SideB { public: Level3() { std::cout << "Level3 ctor" << std::endl; } }; int main() { Level2 l2; Level3 l3; return 0; }
