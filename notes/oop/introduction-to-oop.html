Introduction to Object Oriented Programming

Object oriented programming starts from the object: a bundle of state and behaviour that owns its own data. Unit 1.1 contrasts that with the structured, procedure oriented style and introduces the vocabulary every later unit builds on.

Unit prose and C++ examples are written from the syllabus and standard C++.

Recall cues

  1. When do we choose a procedure oriented design over an object oriented one, and what changes in decomposition?
  2. What is the difference between a class and an object, and what does data abstraction hide behind an interface?
  3. How does encapsulation use access control to protect state, and what does inheritance add to a base class?
  4. How do polymorphism and dynamic binding use a base class reference or pointer to dispatch to derived implementations?

Part 1 · Objects, classes, and the object mindset ★★★

Unit 1.1 of the syllabus.

1. Structured versus object-oriented programming ★★★ EXAM 1

A procedure oriented program is a sequence of functions acting on shared or global data. An object oriented program groups the data of one concept with the operations that act on it into a single unit: the object. The unit shifts from "what are we computing" to "what are we modelling".

Procedure vs object oriented decomposition of the Time class problem

Procedure style: write addHours, addMinutes, addSeconds functions and pass hours, minutes, seconds around as parameters. Object style: put hours, minutes, seconds inside a Time class and let member functions read and transform them together.

2. Class, object, and data abstraction ★★

A class is a blueprint; an object is a concrete instance built from it. Data abstraction names the idea: expose what a caller needs, hide how it is stored.

3. Encapsulation ★★ EXAM 2

Encapsulation bundles state and behaviour into one unit and gates access through access specifiers, so callers use an interface instead of touching raw fields.

4. Inheritance and polymorphism ★★ EXAM 15

Inheritance builds a derived class from a base class, reusing and extending behaviour. Polymorphism lets one interface name many implementations, realised through dynamic binding.

5. Dynamic binding and message passing ★ EXAM 5

Dynamic binding resolves a call at runtime through a base class pointer or reference, so a derived override wins. Message passing is the object asking another object to do work.

6. OOP features and use ★★ EXAM 4

Object-oriented features work together: classes and objects model real entities; encapsulation hides representation; abstraction exposes only what callers need; inheritance reuses and extends base classes; polymorphism lets one interface name many implementations; dynamic binding selects the override at runtime. Reusability and maintainability follow.
